# Spine Pair Review — WORKING HARD with EXCEL

## Overall verdict
A downstream consumer can extract cleanly from this pair. All 56 color tokens have hex values and light pairs, every `{path}` reference resolves, all 35 component names match across both spines, and every V1 CAP is covered by a named El Zavier journey with a climax. Three high issues stand between this draft and `final`. Results breaks the CAP-5 contract by hiding correct questions. Finalize also has housekeeping left: nothing is promoted to `mockups/`, and both files are still `status: draft`.

### Findings
- **high** Light mode is a committed V1 feature: there is a Theme Toggle in the Header Bar and in Settings (EXPERIENCE.md § Foundation, § Component Patterns Theme Toggle). Yet DESIGN.md § Colors says "do not ship light mode before resolving" its AA failures, so the `-light` tokens are not final for half the contract. A developer will build the toggle with failing tokens. *Fix:* decide now. Either tune the light tokens (for example, darken `primary-light` until white text reaches 4.5:1, and darken `streak-light`, `success-light`, `destructive-light` and `warning-light` for text on `*-soft`), or remove the light mode and Theme Toggle from V1.
- **medium** The contrast table measures the wrong pair for the Streak Chip and leaves out several state-bearing pairs. Re-measured: Streak Chip and Streak Risk Pill are `streak` on `streak-soft` (dark 5.5, **light 2.8, which fails even 3:1**). Freeze Pill `chart-2` text on card is light 3.2, failing as text. The passed Level Node stroke, `primary` on `accent`, is light 2.9, under the 3:1 UI minimum. Pending Practice Pips (`muted` vs `card`, about 1.1) carry state through color alone and are near-invisible. The Level Path base trail (`border` vs `card`) is 1.3 (DESIGN.md § Colors contrast table; § Components Streak Chip, Freeze Pill, Level Node, Practice Pips). *Fix:* add these rows and tune the tokens, or give pending pips an outline or label.
- **medium** The Freeze Pill and the frozen Week Strip day use a "faint teal fill with teal hairline border", but no token exists for it. There is no `chart-2-soft` or `freeze-soft`, and the `freeze-pill` frontmatter has no `background` (DESIGN.md frontmatter `components.freeze-pill`; § Components Freeze Pill). *Fix:* add `freeze-soft` with a light pair using the 14% rule, and reference it.
- **medium** The Records Card text and digit color is undefined (only the colon is `{colors.primary}`). In light mode its gradient `accent-light → primary-foreground-light` (`#E3F6EB → #FFFFFF`) is a light card, so the "Inverted card" spec contradicts itself (DESIGN.md frontmatter `components.records-card`; § Components Records Card). *Fix:* add `records-card.foreground`, and state the light-mode gradient explicitly or keep the card dark in both modes.
- **low** The `success` and `success-soft` role is "'Correct' marks in Results", but Results never lists correct questions (EXPERIENCE.md § Component Patterns Wrong Answer Row). `streak-glow` (non-strong) is also never used (DESIGN.md § Colors). *Fix:* name a real use site, such as the "Semua benar!" line or the History detail, or drop the tokens.

## 4. State coverage — adequate
Checked: I walked all 15 IA surfaces. Login, Dashboard (first run, loading and four streak states), Level Map and Detail, Exam in progress (10 states), Results (6 variants), the empty and loading states of the collection pages, global sign-out and network error, the V1 Under Construction state and focus are all covered well. The gaps cluster around the long-lived exam attempt.

### Findings
- **high** The active-attempt lifecycle is unresolved and is parked in Open Questions, yet the climaxes of J0, J1 and J4 depend on the exam page being open so it can "move to Results by itself" (CAP-3). There is no state for: the tab closed or navigated away during an attempt; a graded result arriving while the user is on Dashboard or on another device; pressing Start while an attempt is open; reloading the Exam in progress page (EXPERIENCE.md § State Patterns "Active attempt exists → See Open Questions"; § Open Questions). *Fix:* decide before architecture. One option is a resume-exam banner on every signed-in surface plus a "Result ready" Toast or route, with Start replaced by "Resume exam" while an attempt is open, and the exam page rehydrating from the server on load.
- **medium** Session expiry while the exam is running is unspecified. The global rule "signed out / session expired → Redirect to Login" would strand the auto-move to Results, and hints and upload need auth (CAP-17) (EXPERIENCE.md § State Patterns last rows). *Fix:* keep the session alive on Exam in progress, and/or return to the active attempt after re-login.
- **medium** No state covers the Start or download step failing (the `.xlsm` never downloads or is blocked by the browser). Grading that takes long or fails after the file is received has no state either (EXPERIENCE.md § State Patterns Exam in progress). *Fix:* add "Download didn't start — Download again" and a grading-delay or grading-failed state with retry.
- **medium** Only refresh failures are covered. "Network error → last loaded data stays visible" assumes data already exists, so no surface has a first-load failure state (EXPERIENCE.md § State Patterns "Any surface / Network error"). *Fix:* add a cold-load error treatment, such as an inline retry in the Skeleton area.
- **low** Smaller gaps: Start on the phone (Open Question), Results opened from History (loading and route), and Level Detail Panel loading. *Fix:* fold these in when the Open Questions are resolved.
